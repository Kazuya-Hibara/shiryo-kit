# ports.md — 工程 (Port) の契約

各工程について、入力・出力・必要な能力・能力が無い時・失敗した時を決める。
道具やモデル (Adapter) は、この契約を満たせば差し替えてよい (割当表は `adapters.md`)。
工程の順番は SKILL.md「進め方」が正。

## 能力の確認

始める時に一度確かめ、BRIEF.md の「環境」に書く。思い込みで「ある/無い」を決めない。手元の道具一覧と、実際に 1 回試した結果で決める。

| 能力 | 確かめ方 | 無い時 |
|---|---|---|
| 質問 UI (選択式で答えられる画面) | 使える道具の一覧に、利用者へ選択式で質問する道具があるか | 番号付きの文章で聞く (`hearing.md` §質問票の形)。質の差は無い |
| subagent | 使える道具の一覧に、別の文脈で作業させる道具があるか | 別プロセス (新しく起動したモデル) を試す。それも無ければ検品は「未検品」 |
| 別プロセス | `codex exec --help` や `claude --help` など、モデルを新しく起動する command が動くか | subagent を使う。両方無ければ「未検品」 |
| Web 取得 | 公的なページを 1 つ実際に取得してみる (例: e-Gov 法令検索) | 主張は全部「未確認」にして [要確認] を付け、利用者に「この環境では原典を取りに行けません」と伝える |
| ファイル読取 | 渡された pptx・pdf・docx を 1 つ開いてみる | `markitdown` (Python) があれば使う。無ければ本文を貼ってもらう |
| 書き出しの実行 | `node --version` (22 以上)、`python3 --version` (3.10 以上)、`python3 -c "import pptx"`、Chrome の有無 | 本人の了承を得て準備する (何を入れるかを平易に説明する)。了承が無ければ HTML と PDF 印刷の手順だけ渡す |
| プレビュー表示 | `python3 scripts/preview.py <案件フォルダ>` が起動するか (`html-contract.md`) | ファイルを直接開いてもらう。修正は会話で受ける |

## P0 下調べ

- 目的: 質問の前に、聞かなくて済むことを埋める。
- 入力: 作業フォルダ、`資料メモ/` (あれば)、本人が渡した過去資料・参考資料、依頼文。
- 出力: 読んだ物の一覧 (読めなかった物と理由つき)、推奨答の素 (メモと資料から分かったこと、出典 file つき)、口調の候補 (`voice.md`)。
- 必要な能力: ファイル読取。量が多い時は subagent (要点だけ返させる)。
- 無い時: 本文を貼ってもらう。貼られた分だけを読んだと言う。
- 失敗時: 読めなかった file を一覧に「読めませんでした (理由)」と出し、それを前提にした推奨答を作らない。
- 守ること: 別の顧問先の案件限定メモを読まない。顧問先の個人情報を写さない。`資料メモ/訂正ログ.md` の「使わない」を守る。

## P1 ヒアリング

- 目的: 作る前に、資料要件を本人と合意する。
- 入力: P0 の出力、依頼文。
- 出力: 本人が承認した要約 (BRIEF.md の素)。
- 必要な能力: 利用者との対話。質問 UI があれば使う。
- 無い時: 番号付きの文章で聞く。
- 失敗時: 止める項目 (目的・受け手・成果物) が埋まらない → 作らずに、何が決まれば作れるかを伝えて待つ。本人が答えない問いは「未確定」として残し、推奨答を承認扱いにしない。
- 詳細: `hearing.md`。

## P2 BRIEF (資料要件の正本)

- 目的: 以後の全工程が読み直す正本を 1 つにする。
- 入力: P1 の承認済み要約。
- 出力: 案件フォルダの `BRIEF.md` (`brief-template.md`)。承認記録つき。
- 必要な能力: ファイル書込。
- 無い時: 会話に BRIEF 全文を出し、本人に保存してもらう。以後は毎回それを貼り戻してもらう。
- 失敗時: 承認記録が書けない限り P4 に進まない (関門 1)。
- 変更: 合意済みの要件を変えるのは本人の言葉だけ。決定ログに追記し、spec_rev を上げる。

## P3 出典台帳

- 目的: 確認が要る主張を漏れなく拾い、原典で確かめる。
- 入力: BRIEF.md、骨子と下書き (スライド・読み原稿・図表・配布資料)、本人提供の資料。
- 出力: `ledger.md` (書式は `html-contract.md`)、`sources/` の抜き書き、外に送った検索語と取得した URL の一覧。
- 必要な能力: Web の検索と取得 (Claude Code = WebSearch・WebFetch か shell の curl、Codex = Web 検索か shell の curl。`evidence.md` §3)。
- 無い時: 全主張を「未確認」にし、資料に [要確認] を出す。
- 失敗時: 取得失敗・リンク切れ・内容不一致・基準日に有効でない → 「未確認」(理由つき)。推測で数字を埋めない。
- 守ること: 検索語に顧問先の個人情報や社名を入れない。モデルの記憶だけで「確認済み」にしない (関門 2)。
- 詳細: `evidence.md`。

## P4 骨子と下書き

- 目的: 型を使い、結論が先に分かる資料を作る。
- 入力: BRIEF.md、`assets/kata/` の型、`資料メモ/事務所共通.md` (口調の節)、出典台帳。
- 出力: `deck.html` (読み原稿を含む。形は `html-contract.md`)、求められた他の成果物。
- 必要な能力: ファイル書込。
- 前提: BRIEF.md に承認記録がある (関門 1)。
- 失敗時: 型に合わない依頼 → 近い型を土台に組み替え、BRIEF の型欄に「組み替え」と書く。要件どうしが矛盾 → 根拠を見せて本人に 1 回で聞く (新しい事実による質問として扱う)。
- 判断の軸: `doctrine.md`。

## P5 検品

- 目的: 作り手の思い込みを、別の目で見つける。
- 入力 (reviewer に渡す path はこれだけ): `BRIEF.md`・`ledger.md`・`deck.html`。reviewer はそこから辿れる `sources/`・`out/` と原典の URL を自分で開き、`scripts/check.py` を道具として使う。
- 出力: `review/review-<n>.md` (結論・指摘) と、`scripts/review_record.py` が書く独立の記録 (`review/independence-<n>.json`、別プロセスなら `run-<n>.jsonl` も)。進行役は記録を手で書かない (自己申告にしない)。`check.py review-evidence review` が通ること。
- 必要な能力: subagent か別プロセス (起動は `review_record.py start`/`finish` か `review_record.py run` を通す)。
- 無い時: 機械チェックと作り手自身の点検はしてよいが、結果を「未検品」と表示する (関門 4)。自分の点検を「独立検品」と呼ばない。
- 失敗時: reviewer が起動しない・途中で落ちる・`review-evidence` が通らない → 1 回だけ起動し直す。だめなら「未検品」。納品前の `check.py manifest out review` が通らない → 検品し直すか「未検品」。指摘が既定 2 巡の直しで尽きない → 残りを本人に見せて判断を仰ぐ。
- 詳細: `review.md`。

## P6 書き出し

- 目的: 本人が直せる形で渡す。
- 入力: deck.html。
- 出力: `out/` の pptx (本文がテキストボックス・表として直せる)、PDF、読み原稿。
- 必要な能力: Node・Chrome・Python (python-pptx)。
- 無い時: 準備の了承を得る。了承が無ければ HTML を渡し、pptx は作れていないと伝える。
- 失敗時: `scripts/build.py` が失敗 → 出力の理由を読んで 1 回直す。`scripts/check.py pptx` で欠落・画像化が出たら、その版を納品しない。
- 使い方: `html-contract.md`。代わりの描画部品: `adapters.md`。

## P7 修正

- 目的: 自然言語の指示で直し、直した後も正しさを保つ。
- 入力: 本人の指示 (会話、または画面で指した場所とコメント)、BRIEF.md、versions.md。
- 出力: 新しい版と、`versions.md` の追記。
- 必要な能力: P3・P5・P6 と同じ。
- 失敗時: 指示がどこを指すか分からない → 候補を示して確かめる (これは新しい要件の質問ではない)。指示が合意済みの要件を変える → 決定ログに追記し spec_rev を上げてから直す。
- 詳細: `revision.md`。

## P8 メモリー

- 目的: 2 回目以降、同じことを聞き直さない。
- 入力: BRIEF.md、本人の訂正、voice の抽出結果。
- 出力: `資料メモ/` の追記・更新 (`memory.md`)。
- 必要な能力: ファイル書込、`scripts/check.py pii`。
- 無い時: 保存する内容を会話に出し、本人に保存してもらう。
- 失敗時: `check.py pii` が個人情報を見つけた → その行を消すか一般化してから見せ直す。本人の了承が無い → 保存しない。
