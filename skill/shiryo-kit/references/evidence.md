# evidence.md — P3 出典台帳 (確かめた事実だけを「確認済み」と呼ぶ)

## 目的

士業の資料で一番怖いのは、もっともらしい間違い (古い制度・未施行の改正・対象違い・作られた数字)。
この工程では、資料の中の確認が要る主張を漏れなく拾い、原典の本文を取得して照合し、確かめられなかったものを隠さず見せる。

## 絶対の決まり

- 「原典確認済み」と書けるのは、この案件で原典の本文を取得し、該当箇所を引用として `sources/` に残し、主張と一致し、基準日時点で有効だと確かめたものだけ。
- モデルの記憶・解説記事・他の事務所のサイト・まとめサイト・過去の資料は、確認の根拠にしない (原典を探す手がかりには使ってよい)。
- 取得できない・リンク切れ・内容が違う・基準日に有効でない → 「未確認」。理由を書く。
- 未確認の主張は、資料のその場所に [要確認] を出す。数字・日付・金額は推測で埋めない (「助成額 [要確認]」のように書く)。
- 検索語に顧問先の名前・従業員の情報・案件の固有情報を入れない。外に送った検索語と取得した URL は記録し、最後に利用者へ一覧で見せる。

## 1. 主張を抜き出す

骨子の段階で一度、下書きの後にもう一度、**全部の成果物から** 抜き出す。下書きで主張が増えるため、2 回目を省かない。

見る場所: スライドのタイトル・本文・図のラベルと数値・表の各セル・注記と脚注・読み原稿 (話す言葉)・配布資料・表紙の日付。

確認が要る主張:
- 法令の条文・制度の説明 (「〜が義務になった」「罰則がある」「努力義務」)
- 金額・率・上限・下限 (保険料率、最低賃金、助成額、割増率)
- 日付・期限・期間 (施行日、申請期限、「来年 4 月から」)
- 対象・要件 (企業規模、人数、業種、年齢、被保険者の区分)
- 手続き・様式・提出先
- 統計・調査の数字
- 比べる言い方 (「〜より有利」「全国平均より高い」)

隠れた主張に注意する: 「すべての会社が対象」(対象の主張)、「今年から」(日付の主張)、「必ずもらえる」(要件と受給の主張)。相対的な日付は基準日をもとに年月日に直してから確かめる。

確認が要らないもの: 話し手の意見・経験談 (意見として書かれている限り)、事務所自身のサービス内容と料金 (本人提供)、明らかに架空と分かる例 (「例」と表示する)。

## 2. 区分

| 区分 | 意味 | 資料での見せ方 |
|---|---|---|
| 原典確認済み | 上の絶対の決まりを全部満たした | 出典を表示 (型の出典欄・脚注) |
| 未確認 | 確かめられなかった。理由は: 原典なし / 取得失敗 / リンク切れ / 原典と食い違い / 旧制度 / 未施行 / 対象違い / 年度・地域違い / 改正案で未決 | その場所に [要確認] |
| 本人提供 | 本人が言った・本人が渡した資料にあった (公的な原典を取得して照合していない) | 原典で確かめられればそうする。できなければ、最後の報告で「本人提供 (原典未照合)」として一覧に出す |

本人提供の数字が原典と食い違ったら、黙って直さない。どちらが正しそうかの根拠を見せて本人に聞く (新しい事実による質問)。

台帳の列と書式は `html-contract.md` が正 (`scripts/check.py ledger` がそれを読む。2026-10-18 時点の列は ID・主張・表記・区分・出典URL・取得日・引用・適用時点・使用箇所・備考。区分の語は「確認済み / 未確認 / 本人提供」、未確認の理由は備考に書く)。意味はこの file に従う。台帳の各行に最低限必要なこと: 番号・資料での書き方・場所 (スライド番号と、本文/図/表/原稿のどこか)・種類・区分・未確認の理由・出典 URL・取得した本文の該当箇所 (引用)・取得できたか・確認日・適用時点 (施行日・経過措置・対象・未施行か)。

## 3. 原典の取り方

優先順: ① 法令の本文 → ② 所管の官庁の説明・通知 → ③ 実施する機関の案内 → ④ 公募要領・支給要領 (最新の年度版)。二次情報は手がかりだけ。

| 種類 | 原典 |
|---|---|
| 法律・政令・省令の本文、附則 (施行期日・経過措置)、改正の履歴と未施行の改正 | e-Gov 法令検索 https://laws.e-gov.go.jp/ |
| 公布されたか・公布日 | 官報 https://www.kanpo.go.jp/ |
| 労働・社会保険の制度説明、法改正のお知らせ、通達 | 厚生労働省 https://www.mhlw.go.jp/ (法令・通知は 厚生労働省 法令等データベース) |
| 雇用関係の助成金 (支給要領・申請期間・受付停止の告知) | 厚生労働省の助成金のページ、各都道府県労働局 |
| 地域の運用・最低賃金・窓口 | 各都道府県労働局 https://jsite.mhlw.go.jp/ (例: 東京労働局は tokyo-roudoukyoku) |
| 年金・厚生年金保険の手続きと保険料 | 日本年金機構 https://www.nenkin.go.jp/ |
| 協会けんぽの保険料率 (都道府県別・年度別) | 全国健康保険協会 https://www.kyoukaikenpo.or.jp/ |
| 中小企業の施策・補助金 | 中小企業庁 https://www.chusho.meti.go.jp/、各補助金の公式サイトの公募要領、jGrants https://www.jgrants-portal.go.jp/ |
| 税の扱い | 国税庁 https://www.nta.go.jp/ |
| 自治体の制度・助成 | 各自治体の公式サイト |

### 環境ごとの取得の道具

| 環境 | 探す | 本文を取る |
|---|---|---|
| Claude Code | Web 検索の道具 (WebSearch) | Web 取得の道具 (WebFetch) で読む。ただしこの道具は要約して返すことがあるので、引用は下の「生の本文」で必ず確かめる。生の本文は shell の `curl -sL -o sources/raw/<番号>.<html か pdf> <URL>` で保存する。PDF は保存した file をそのまま読む (読み取りの道具は PDF を読める) |
| Codex | Web 検索 (使える設定の時) | shell の `curl` で `sources/raw/` に保存して読む。サンドボックスでネットが閉じている時は、利用者に許可を求めるか、取れないものとして扱う |
| どちらでも | 本人が URL を知っている時はそれを使う | — |

生の本文の文字を取り出す (HTML は標準ライブラリだけで足りる):

```
python3 -c "import re,sys,html;t=open(sys.argv[1],encoding='utf-8',errors='ignore').read();t=re.sub(r'(?is)<(script|style).*?</\1>','',t);print(html.unescape(re.sub(r'<[^>]+>',' ',t)))" sources/raw/<番号>.html > sources/raw/<番号>.txt
```

PDF は、読み取りの道具で直接読むか、`pdftotext` があれば `pdftotext sources/raw/<番号>.pdf sources/raw/<番号>.txt`。どれもできなければ未確認 (取得失敗)。

引用は、生の本文に同じ文字列があることを確かめてから台帳に入れる (`grep -F "<引用>" sources/raw/<番号>.txt`、空白や改行の違いは詰めて比べる)。見つからない引用は使わない。台帳を書いた後は `check.py ledger` が、台帳の隣の `sources/` (`raw/` の下も含む .txt・.md・.html) の本文と、確認済みの引用を自動で照らす。PDF は .txt にして置く (そのままでは照らせない)。8 字未満の断片は照らさない。要約の道具が返した文を、そのまま引用として扱わない。

失敗の扱い: 検索で原典が見つからない → 未確認 (原典なし)。取得が 404・タイムアウト・403 → 未確認 (取得失敗 / リンク切れ)。本文に主張と合う箇所が無い → 未確認 (原典と食い違い)。どれも推測で埋めない。

取り方の注意:
- PDF の公募要領・リーフレットは本文を読む。読めなければ未確認 (取得失敗) にする。
- 自動の取得を断るサイトがある (2026-10 時点で中小企業庁のサイトは自動取得に 403 を返した)。取れなければ未確認 (取得失敗) とし、本人に開いて確かめてもらう場所を伝える。本人が開いて本文を貼ってくれたら、それを引用にしてよい (取得方法に「本人が貼付」と書く)。
- 同じ名前の資料に年度版がある時は、基準日に有効な版を選び、版 (例「令和 8 年度版」) を記録する。
- 取得できなかった時は、どこで確かめればよいか (ページ名・窓口) を [要確認] の説明として本人に伝える。

## 4. 引用を残す

取得したら、生の本文 (`sources/raw/`) とは別に `sources/<番号>.md` に次を残す (reviewer が開き直せるように):
- URL、ページや資料の題名、版・年度、取得日時
- 主張を支える該当箇所の本文 (そのまま写す。前後の意味が分かる最小限)
- 条番号・頁番号・表の名前
- 施行日・適用期間・対象について書いてある箇所の本文

台帳の引用欄には、この抜き書きの該当部分を入れる。引用が無い行は「確認済み」にできない。

## 5. 照合する

- 数字は単位と条件まで一致させる (月額/日額、以上/超、税込/税抜、労働者数の数え方)。
- 主張が原典より強くないか (「できる」を「必ず」、「努力義務」を「義務」にしていないか)。
- 原典の条件を資料が落としていないか (「中小企業のみ」「一定の要件を満たす場合」)。

## 5b. 機械で突き合わせる

台帳を書いたら、すべての成果物 (スライドと読み原稿が入った deck.html、配布資料、書き出した読み原稿) と突き合わせる:

```
python3 scripts/check.py ledger ledger.md deck.html [配布資料.html ...] [out/<名前>_読み原稿.md]
```

FAIL (台帳に無い数字・確認済みなのに引用と値が違う・引用が原典の本文に無い・未確認なのに [要確認] が無い) は全部直してから先へ進む。`sources/` が無いと「引用を原典の本文と照らしていない」の WARN が出る。別の場所に原典を置いた時は `--sources <file かフォルダ>` を付ける。

## 6. 適用時点を確かめる

基準日 (BRIEF の frontmatter) 時点で有効かを、毎回確かめる。

| 罠 | 確かめ方 | 扱い |
|---|---|---|
| 旧制度 | 改正の履歴を見て、基準日に有効な版の本文と照らす | 古い内容なら未確認 (旧制度)。今の内容で書き直せるなら原典を取り直す |
| 公布済み・未施行 | 附則の施行期日と基準日を比べる | 基準日に未施行なら、今の制度として書かない。「◯年◯月◯日施行予定」と施行日の原典つきで書き分ける |
| 経過措置 | 附則の経過措置を読む | 対象によって旧ルールが続くなら、その条件を資料に書くか、未確認にする |
| 対象違い | 企業規模・人数・業種・年齢・区分の条件を読む | 受け手の会社に当てはまらない内容を一般論として書かない |
| 年度・地域違い | 料率・最低賃金・助成額の年度と都道府県を確かめる | 基準日の年度・受け手の地域の値でなければ未確認 |
| 受付状況 | 助成金・補助金の公募期間・受付停止・要領の改定日 | 受付が終わっている・改定が予告されているなら、その旨を書く |
| 改正案 | パブリックコメント・審議中の法案は決まっていない | 決まったこととして書かない |

使う日が基準日より後なら、使う日にも有効かを一言確かめ、変わりそうなら最後の報告で伝える。

## 7. 保存した出典を使い回す時

`資料メモ/事務所共通.md` の「よく使う出典」は手がかり。新しい案件で使う時は必ず取り直し、内容・版・年度が変わっていないかを確かめてから「確認済み」にする。変わっていたらメモの方も直す案を P8 で本人に見せる。

## 8. 最後の報告に出すもの

- [要確認] の一覧: 主張・場所・理由・どこで確かめればよいか
- 本人提供 (原典未照合) の一覧
- 外に送った検索語と取得した URL の一覧
