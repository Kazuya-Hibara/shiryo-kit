# voice.md — 本人の口調と構成の癖を抜き出して使う

## 目的

出来た資料が「AI が作った一般的な資料」ではなく「この人の資料」に読めるようにする。
本人の過去資料から、口調 (言葉づかい) と構成の癖 (組み立て方) を、根拠つきで抜き出し、本人に確かめてから使う。

## 抜き出す (P0)

### 1. 読む物を決める

- 本人に、過去の資料 (pptx・pdf・docx)・読み原稿・ブログ・メールマガジン・挨拶文などの場所を聞く。ディスク全体を勝手に探さない。
- 読む予定の file を一覧で見せてから読む。
- 3〜5 点あれば十分。多い時は、今回の資料と種類が近いもの (セミナー資料ならセミナー資料) を優先する。
- 量が多い時は subagent に読ませ、下の 6 つの観点の抜き出しと引用だけを返させる (本文を丸ごと持ち帰らせない)。

### 1b. 読み方 (道具を入れずに読む)

- PDF: 読み取りの道具で直接読む (Claude Code・Codex とも、file を開けば読める)。読めなければ `pdftotext` (あれば)。
- pptx・docx: 中身は zip の中の XML なので、Python の標準ライブラリだけで文字を取り出せる。`markitdown` が入っていればそれでもよい。
- 取り出した文字は案件フォルダの `work/past-materials.md` に、file 名と枚番号 (頁) つきで置く。この file は案件の中だけで使い、メモ (`資料メモ/`) や BRIEF に写さない (顧問先の情報が混ざるため)。

pptx (スライドとノートを枚ごとに):

```
python3 - 過去資料.pptx <<'EOF'
import re, sys, zipfile
z = zipfile.ZipFile(sys.argv[1]); names = z.namelist()
num = lambda n: int(re.search(r'(\d+)\.xml$', n).group(1))
txt = lambda n: ' '.join(re.findall(r'<a:t>([^<]*)</a:t>', z.read(n).decode('utf-8')))
for n in sorted([n for n in names if re.match(r'ppt/slides/slide\d+\.xml$', n)], key=num):
    print(f'## {num(n)} 枚目\n{txt(n)}')
    note = f'ppt/notesSlides/notesSlide{num(n)}.xml'   # 番号がずれる資料もある。ずれたら枚の対応は目で確かめる
    if note in names:
        print(f'(ノート) {txt(note)}')
EOF
```

docx (段落ごとに):

```
python3 - 過去資料.docx <<'EOF'
import re, sys, zipfile
x = zipfile.ZipFile(sys.argv[1]).read('word/document.xml').decode('utf-8')
for p in x.split('</w:p>'):
    t = ''.join(re.findall(r'<w:t[^>]*>([^<]*)</w:t>', p))
    if t.strip():
        print(t)
EOF
```

読み終えたら「読んだ物 / 読めなかった物 (理由)」を一覧で本人に見せる (P0)。

### 2. 6 つの観点で見る

| 観点 | 見ること | 例 |
|---|---|---|
| 語尾と敬語 | です・ます か、だ・である か、タイトルと本文で違うか、呼びかけ方 | タイトルは体言止め、本文は「〜です」、聴衆に「皆さま」 |
| よく使う言い回し | 決まり文句、つなぎの言葉、締めの言葉 | 「ポイントは 3 つです」「現場ではこうなりがちです」 |
| 文の長さと調子 | 短く言い切るか、丁寧に段階を踏むか | 1 行 20 字前後で言い切る |
| 構成の癖 | 冒頭で何を言うか、事例の入れ方、まとめ方、質問の時間、最後の 1 枚 | 冒頭に「よくある相談」、最後に「今日やること 3 つ」 |
| 数字と出典の書き方 | 出典をどこに書くか、和暦/西暦、数字の丸め方 | 出典はスライド下に小さく、和暦併記 |
| 使わない言い方 | 過去資料に一度も出てこない・本人が避けている表現 | 「〜しましょう!」の感嘆、カタカナ語の多用 |

### 3. 決まり

- 2 点以上の資料で見えた癖だけを「癖」と呼ぶ。1 点だけなら「1 点のみ」と書く。
- 抽象的な言い方 (「丁寧」「親しみやすい」) で済ませず、本人の実際の言い回しを「」で 5〜10 個引用し、それぞれに file 名とページ (スライド番号) を付ける。
- 引用に顧問先の名前・個人の情報が入っていたら、その引用は使わない (別の引用を探す)。
- 過去資料の中に AI が書いたと思われる定型句 (「〜を深掘りします」「いかがでしたか」の類) があれば、本人の癖として採らず、確認の時に「これは本人の言い方ですか」と聞く。
- 根拠が無い観点は「(未設定)」のまま残す。もっともらしく埋めない。
- `資料メモ/訂正ログ.md` で「使わない」とされた言い回しは拾い直さない。

### 4. 本人に確かめる

抜き出した結果を短く見せ、合っているか聞く (P1 の問いと同じ回にまとめてよい)。

```
過去の資料 4 点から、話し方の特徴をこう読み取りました。違う所があれば直してください。
- 語尾: タイトルは言い切り (体言止め)、本文は「です・ます」 — 例「残業代の計算ミスが多い 3 つの場面」(セミナー資料_2025春.pptx 3 枚目)
- よく使う言い回し: 「現場ではこうなりがちです」(同 5 枚目、顧問先説明_賃金.pdf 2 頁)
- 構成: 最初に「よくある相談」を 1 枚、最後に「今日からできること」を 1 枚
- 使わない言い方: 感嘆符、「〜しましょう!」
```

2 回目以降で、保存済みの口調 (`資料メモ/事務所共通.md` の口調の節) を推奨答に出す時も同じ形にする。「前回の口調のまま」とだけ書かず、柱とよく使う言い回しを具体的に並べる (例: 「ざっくり言うと」でまとめる / 家計簿のたとえ話)。本人が「それはもう使わない」と直したり消したりできる機会を作るため。

抜き出しの結果は、まず `work/voice-draft.md` に下の「口調の節の形」で書く。本人に確かめた結果を、`資料メモ/事務所共通.md` の「口調と構成の癖」の節の案にする (保存は P8 で見せてから)。

### 口調の節の形 (資料メモ/事務所共通.md の中)

```markdown
## 口調と構成の癖
確認日: 2026-10-18 / 確かさ: 中 (資料 4 点から。直しのたびに更新)

### 柱 (3〜5 個)
- <1 行の説明> — 根拠: <file / 頁>

### よく使う言い回し
- 「<そのままの引用>」 — <file> <頁>

### 構成の癖
- 冒頭: / 事例: / まとめ: / 最後の 1 枚:

### 数字と出典の書き方
-

### 使わない言い方
-

### 未設定
- <根拠が無かった観点>
```

## 資料が少ない・無い時

- 1〜2 点しか無い: そこから抜き出し、確かさを「低」にする。
- 資料が無い: 本人が普段書いている文章 (メール・ブログ・挨拶文) を 1〜2 段落もらう。それも無ければ、同じ内容を 3 通りの口調で書いた短い見本 (例: きっちり丁寧 / やわらかく親しみ / 端的に言い切り) を見せて選んでもらう。好みは言葉で聞かず、見本で選ばせる。
- どの場合も、ヒアリングでの本人の話し方そのもの (言い回し・語尾) を手がかりにしてよい。その時は出典を「ヒアリング <回>」と書く。
- 確かさが低いうちは、資料の文面を強く寄せすぎない。直しの指示から少しずつ育てる (下)。

## 反映する (P4b)

- 文面・読み原稿・構成 (冒頭・事例・まとめ・最後の 1 枚) に、voice.md の柱と構成の癖を入れる。
- 決まった言い回しは、自然に入る所にだけ使う。毎枚に入れない。
- 本人の定型句 (締めの一言・決まり文句・事務所の案内の文) は、そのままの言葉で使い、書き換えない。制作中に直した方がよいと考えた時 (言い過ぎ・制度と合わないなど) も、書き換えずにそのまま使い、直す案と理由を最後の報告で提案する (承認の後に好みの質問はしない。`hearing.md` §作っている途中の質問)。本人が直すと言ったら P7 で直し、決定ログに書く。制度の事実と合わない定型句 (原典と食い違う言い方) は、新しく分かった事実として作っている途中に聞いてよい。
- 型 (`assets/kata/`) の既定の文言と本人の癖がぶつかったら、本人の癖を優先する。
- BRIEF の口調欄 (§6) に、reviewer 向けの要点 3 行 (語尾・呼びかけ・避ける言い方) を書く。reviewer はそれで合っているかを見る。
- 読み原稿は、本人が声に出して話す言葉で書く (書き言葉のままにしない)。

## 直しから育てる (P7 → P8)

本人が文面を直した時、その直し方 (どの言い回しをどう変えたか) は口調の手がかりになる。
同じ種類の直しが 2 回以上あったら、口調の節の更新案を作り、P8 で見せてから保存する。1 回だけの直しで癖を書き換えない。
