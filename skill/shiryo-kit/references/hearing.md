# hearing.md — P1 ヒアリング (作る前に聴き切る)

## 目的と考え方

資料の出来は、作る前に何が分かっているかでほぼ決まる。この工程の仕事は「資料要件について本人と認識を揃え、承認をもらう」こと。
決まっているのは、知る必要があること (網羅の地図)・止め時・守る規律だけ。何をどの順に何往復で聞くかはモデルが判断する。固定の質問票を上から読み上げない。

- 調べて分かる事実は聞かない (P0 で読む)。本人にしか決められないことだけを聞く。
- 一度に、今聞ける問いを全部まとめて出す。小出しにしない。
- 各問に推奨答を付け、「はい」で受け入れられるようにする。
- 本人の答えも、その場で確定にしない。必要なものは疑って確かめる。
- 推測で空白を埋めない。分からないものは「未確定」、こちらの推測は「(推測)」と書く。

## 網羅の地図

各項目について「確定」「仮定 (本人が了承)」「未確定 (理由つき)」のどれかになるまで進める。

| 項目 | なぜ要るか | 確定と言える状態 | 種類 |
|---|---|---|---|
| 目的 | 何を残す資料かで構成が変わる | 「この資料で〜してもらう/分かってもらう」と 1 文で言える | **止める** |
| 受け手 (persona) | 言葉の難しさ・例・密度が変わる | 誰が・どの場面で・受け取った後に何を決めるか・何を知っていて何を知らないか (下の §受け手の立て方) | **止める** |
| 成果物 | 作る物と工程が変わる | スライド・PDF・読み原稿・配布資料のどれが要るか、形式 (pptx で直したいか等) | **止める** |
| 持ち帰らせたい行動 | 最後の 1 枚と全体の筋が決まる | 受け手が資料の後にすること 1-3 個 | 仮定可 |
| 場面 | 密度と枚数が変わる | 時間・会場/オンライン・人数・話すのか配るのか (両方か) | 仮定可 |
| 基準日と使う日 | 法令・制度の「いつ時点」が決まる | 資料の基準日 (何年何月何日時点の内容か) と、実際に使う日 | 仮定可 (既定 = 使う日。使う日が不明なら今日) |
| 入れること・言わないこと | 外せない話と地雷を避ける | 必ず入れる話題、触れない話題・言い方、出さない固有名 | 仮定可 |
| 使える資料 | 原典・数字の出どころになる | 本人の資料・顧問先から預かった物・公的資料の有無と場所 | 仮定可 |
| 口調 | 本人らしさ | `voice.md` の抽出結果を本人が確認した、または選んだ | 仮定可 |
| 型 | 骨格と見た目 | 4 つの型のプレビューから選んだ、または型に無い形を言葉で合意 | 仮定可 |

止める項目が 1 つでも空なら作らない。仮定の項目は、推奨答を「仮定」として示し、本人が了承すれば進めてよい。

依存のある項目は順を気にする。例: 場面 (話す/配る) が決まると成果物 (読み原稿が要るか) と型の推奨が変わる。依存先が未確定の問いは、その回には出さず次の回に回す。依存の無い問いは同じ回に全部出す。

## 1 回の問いかけの作り方

1. P0 で分かったことを先に短く見せる (「過去資料 3 点とメモを読みました。次のことは分かっています: …」)。
2. まだ決まっていない項目のうち、今聞ける問いを全部並べる。
3. 各問に、推奨答・なぜ聞くか (答えで資料の何が変わるか) を付ける。推奨答の出どころ (前回のメモ・過去資料・依頼文) も一言添える。
4. 答え方を示す: 「全部この通りでよければ『はい』、変える所だけ『2: 配布のみ』のように番号で」。

### 質問票の形 (質問 UI が無い時)

```
資料づくりの前に、まとめて確認させてください。おすすめの答えを書いてあります。
このままでよければ「はい」、変えたい所だけ番号で教えてください (例: 「3: 40分」)。

1. 目的 — おすすめ: 「就業規則の見直しが必要な会社に、相談に来てもらう」
   (前回のセミナーと同じ目的にしています。目的で最後のまとめ方が変わります)
2. 聞く人 — おすすめ: 従業員 10〜30 人の会社の社長・総務担当
   A. このまま  B. 人事の専門担当が多い  C. その他 (書いてください)
3. 時間と形 — おすすめ: 60 分、会場で投影して話す + 同じ内容を PDF で配る
...
```

- 選択肢は重ならず、漏れが無いようにし、「その他」を必ず付ける。
- 1 問に 2 つのことを混ぜない (「時間と人数は?」は 2 問に分ける)。
- 答えを含む聞き方をしない (「分かりやすい方がいいですよね?」は不可。「専門用語はどこまで使ってよいですか」に)。
- 抽象的なこと (雰囲気・見た目・硬さ) は言葉で聞かず、実例・選択肢・プレビューで聞く。

### 質問 UI がある時

各問を UI の 1 問に対応させ、推奨答を先頭の選択肢に置き「(おすすめ)」と付ける。UI の 1 回に入る問いの数に上限がある時は、続けて次の回を出す。上限を理由に問いを捨てない。自由記述が要る問いは、選択肢の「その他」で受ける。

## 答えを疑う (probe)

本人の答えは「最有力の仮説」として受け取る。資料の形を左右する答えには、次の回で 1-2 個の確かめを返してから確定にする。試す口調にせず「念のため」「違っていたら直してください」と添える。

| 答えの様子 | 確かめ方 |
|---|---|
| 形容詞・意見 (「分かりやすく」「やさしめに」) | 実例で裏を取る: 「前に『分かりにくい』と言われた資料や場面はありますか。どこが引っかかりましたか」 |
| 手段 (「図を多めに」) | 一段上の目的を聞く: 「図を多めにすると、聞く人にとって何が良くなりますか」 |
| 選択肢の番号だけ・即答 | 言い換えて確かめる: 「つまり『…』ということで合っていますか」。逆の読みを示す: 「逆に『…』だとしたら困りますか」 |
| 「全部」「どれも大事」 | 見落としを名指しし、優先順位と外すものを聞く |
| 受け手について | 最近の具体的な場面を 1 つ聞く: 「最近、顧問先の社長から実際に聞かれた質問は?」 |

本人が確かめを退けたら、その答えを確定にし、退けた理由を BRIEF の根拠欄に残す。矛盾した答えはその場で説得せず、矛盾として示して本人に選んでもらう。

## 受け手の立て方

受け手は資料ごとに立てる。保存済みの persona (`資料メモ/事務所共通.md` の「何度も出てくる受け手」か、その顧問先の `資料メモ/案件/<呼び名>.md`) が合えば推奨答にする。無ければ聞いて作る。

persona は 15 行以内で、次を持つ:
- 誰か (呼び名。実名は使わない)
- 受け取る場面 (いつ・どこで・どれくらいの時間で・他に何と並べて見るか)
- 受け取った後に決めること・すること
- 知っていること・知らないこと (専門用語をどこまで知っているか)
- 刺さるもの・嫌うもの (根拠のある範囲で。本人から聞いた言葉は「」で)
- 根拠 (本人の言葉・ヒアリングの回・過去資料)
- 未確定 (論点 / 仮の扱い / 確定の条件)

根拠の無い所は業界の常識で埋めず、未確定に置く。

## 2 回目以降

- 保存メモの値を推奨答として出す (「前回: 顧問先の社長向け・60 分。同じでよければ『はい』」)。
- 事務所共通の情報 (話し手の紹介・口調・型の好み) は、変わっていないかを 1 問でまとめて確かめるだけにする。
- 案件限定の情報は、同じ顧問先・同じ回の続きの時だけ使う。別の顧問先・別の回なら持ち越さず、新しく聞く。
- 結果として、2 回目は数問で済むのが普通。それでも止める項目の承認は毎回もらう。

## 型の見せ方

型は 4 つ (セミナー / 顧問先説明 / 提案 / 報告) が `assets/kata/` にある。各型のプレビューを本人に見せて選んでもらう。
- 見られる環境: プレビューをブラウザで開く (`python3 scripts/preview.py <フォルダ>` で表示できる時はその URL、できなければファイルを直接開いてもらう)。
- 見られない環境: 各型の特徴を 2 行ずつ言葉で示し、ファイルの場所を伝える。
- おすすめの型を 1 つ、理由 (目的・場面との合い方) つきで示す。
- 型に無い依頼 (例: 社内研修の配布資料) は、近い型を土台に組み替える案を言葉で示して了承をもらう。
- 選ばれた型は事務所共通メモの「型の好み」の候補になる (保存は P8 で本人に見せてから)。

## 要約の読み上げと承認

聞き終えたら、BRIEF の要点を 10-20 行で読み上げる。

- 本人が言ったこと、P0 で資料から分かったこと (どの file か)、こちらの推測 (「(推測)」) を分けて書く。
- 了承をもらう仮定は「仮定: 〜で進めます」と 1 行ずつ並べる。
- 未確定のまま進むものは理由と、いつ確定させるかを書く。
- 最後に「この内容で作り始めてよいですか。直す所があれば教えてください」と聞く。

承認と扱うのは、本人がこの要約に対して「はい」「この内容で」などとはっきり答えた時だけ。返事が無い・話題が変わった・「たぶん」は承認ではない。承認の言葉をそのまま BRIEF.md の承認記録に書き、ここで BRIEF を確定する (spec_rev 1)。

## 急いでいる人

「質問はいいから作って」と言われたら、P0 の結果から全項目の推奨答を作り、1 回で全部示して「この前提で作ってよいですか」と聞く。これが承認になれば進む。止める項目の承認は省かない。

## 作っている途中の質問

承認後に質問してよいのは、新しく分かった事実が合意済みの要件を変える時だけ。例:
- 原典を取ったら、本人が入れたいと言った制度が基準日にはまだ施行されていなかった。
- 本人の過去資料に、BRIEF と食い違う方針が書かれていた。

その時は、根拠 (どこに何が書いてあったか) と選択肢と推奨答を 1 回にまとめて聞く。答えを決定ログに追記し、spec_rev を上げる。思いつき・念のための質問・好みの確認はしない。骨子を見せて「この流れで進めます」と伝えるのは確認なので構わない。
