# memory.md — P0 と P8 のメモリー (一度聞いたことを次に活かす)

## 目的

2 回目以降、同じことを聞き直さない。前回の答えを推奨答として出し、変わった所だけ聞く。
ただし、別の顧問先・別の回の情報を持ち込まない。顧問先の個人情報は保存しない。保存も訂正も本人が決める。

## 置き場所

利用者が選んだ作業フォルダの中の `資料メモ/` (名前は仮。本人が別の名前・場所を選んだらそれに従い、BRIEF の環境欄に書く)。
skill フォルダの中には保存しない (更新で消える・書けないことがある)。各ツールの自動メモ機能にも頼らない (無効な環境がある)。正本はこのフォルダの file。

```
資料メモ/
  README.md            このフォルダの説明 (人が読んで分かる 10 行程度)
  事務所共通.md         どの案件でも使う: 話し手・事務所の紹介 (資料に載せてよい範囲) / 口調と構成の癖 (`voice.md` の形) /
                       型と見た目の好み / 本人の方針 (いつも入れる・言わないこと) / よく使う出典 (手がかり) / 何度も出てくる受け手
  案件/<年月>_<呼び名>-<回>.md
                       その顧問先・その回だけ: 受け手 / 場面 / 言わないこと / 前に説明した話題 — 同じ顧問先の同じ回の続きの時だけ読む
  訂正ログ.md           訂正・削除の記録と「使わない」一覧
  pii-allow.txt        個人情報の検査で通してよい語 (本人が載せてよいと言った話し手の氏名・事務所名など)
```

- 呼び名: 顧問先の名前が会話に初めて出た時に、短い呼び名 (例「A 社」「商工会」) をその場で決めて本人に伝える (「メモや作業の file では『A 社』と呼びます。別の呼び名がよければ教えてください」)。以後、メモ (file 名と本文)・BRIEF・subagent への依頼文では呼び名だけを使う (検索語には呼び名も入れない)。顧問先の正式名はメモに保存しない。呼び名は顧問先ごとに別にし、別の顧問先に使った呼び名を使い回さない。資料の本文に顧問先名を載せるか (宛名など) は、BRIEF の「出さない固有名」で本人が決める。
- 案件メモの file 名は `<年月>_<呼び名>-<回>.md` (例 `2026-11_サンプル商工会-本部.md`、`2027-01_サンプル商工会-南支部.md`、`2026-12_A社-社会保険の説明.md`)。年月はその回の使う日の年月。回は「本部」「南支部」「新入社員研修」のように、同じ顧問先の中で回を見分ける短い名前。1 つの回に 1 file。同じ顧問先でも回が違えば別の file にし、前の回の file に書き足さない (回をまたいで混ざると、次に別の回で読んだ時に持ち越しが起きる)。
- 既に `資料メモ/` が別の形で置かれていても、事務所共通と案件限定の区別が読み取れればそのまま使う。保存の時に、この形に寄せる案を見せる。
- 各項目には、値・どこから来たか (どの案件で本人が言った / どの file から抜いた)・最後に確かめた日を書く。

```markdown
## 話し手の紹介
- 値: 社会保険労務士。中小企業の労務相談を中心に…
- 出典: 20261018-就業規則セミナー のヒアリング 1 回目、本人の言葉
- 確認日: 2026-10-18
```

## 読む時 (P0)

1. 作業フォルダとその親を見て `資料メモ/` を探す。見つかったら「メモが見つかりました: <path>」、無ければ「メモは見つかりませんでした。今回の内容は、最後に保存するか確認します」と言う。
2. `訂正ログ.md` を先に読み、「使わない」に当たる内容は以後使わない。
3. `事務所共通.md` を読む。
4. 案件メモ (`案件/`) は、次の手順でだけ開く。他の顧問先・別の回のメモの中身を、会話に入れないため:
   1. `案件/` の中は file の名前だけを一覧にする (`ls 資料メモ/案件/`。Windows は `dir /b 資料メモ\案件`)。中身を読む道具 (cat・head・grep・Read・全文検索) をフォルダ全体や候補の全部に使わない。
   2. 今回の顧問先の呼び名と回を、依頼文から決める。分からなければ開かずに、ヒアリングの最初の問いで「どの顧問先の、どの回向けですか」を聞き、答えが出てから選ぶ。本人が正式名で言って、どの呼び名か結び付かない時は (正式名は保存していないので)、前に付けた呼び名を本人に聞く。file 名の一覧を見せて選ばせない。
   3. 名前の `<呼び名>` と `<回>` が今回と同じ file (同じ回の続き・直し・同じ回の再演) だけを開いて読む。
   4. 同じ顧問先の別の回の file しか無い時は、今回は新しい回として扱う。その file は開かない。前の回の受け手・場面・時間・言わないこと・話題は、今回の推奨答にしない。本人には、最初の問いの中で 1 回だけ中立に聞いてよい: 「<呼び名> の前の回のメモ (<file 名>) があります。参考にしますか (中身はまだ開いていません。今回は別の回なので、受け手や場面は新しく伺います)」。この問いには推奨答を付けない (「はい」「いいえ」のどちらにも寄せない例外。ほかの問いの推奨答の決まりは `hearing.md` のまま)。中身・前の回の受け手や場面・「同じ相手として使う」の提案は出さない。答えが無い・「いいえ」なら開かない。同じ問いを繰り返さない。本人が「参考にする」「前の回のメモを使って」と言った時だけ開き、使う項目を 1 つずつ本人に確かめる (確かめた項目は今回の本人の答えとして BRIEF に書く)。開かないのは、別の回の受け手を推奨答に出すと、違う相手向けの資料になる事故が起きるため (CC1-1 の事故は推奨答の方で、聞くこと自体ではない。前の回を開いて「参考」として見せると、推奨答に引きずられる)。
   5. 名前だけでは決められない時 (呼び名が似ている・回の名前が分からない・回の入っていない古い形の file 名) は、開かずに、今回の顧問先の呼び名と同じ呼び名の file 名だけを並べて「今回はどれの続きですか」と聞く。呼び名が違う file は、似ていても並べない (別の顧問先の名前を本人に見せないため)。推奨答は「どれの続きでもない (新しい回として伺う)」にする。
   6. 他の顧問先の file は開かない。その file 名も本人への問いに出さない。誤って開いた時は、中身を使わず、開いたことを本人に伝える。
5. 読んだ値は推奨答として使う。確定値としては扱わない (本人が「はい」と言って初めて今回の要件になる)。
6. `sources.md` の出典は、使う前に必ず取り直す (`evidence.md` §7)。

## 保存する時 (P8)

1. 案件の終わり (または本人が望んだ時) に、保存の案を作る。分け方:
   - 事務所共通: 話し手・事務所の紹介、口調、型の好み、よく使う出典、何度も出てくる受け手
   - 案件限定: その顧問先・その回の受け手と事情。file は回ごとに分け、名前は `案件/<年月>_<呼び名>-<回>.md` (§置き場所)。回の入っていない古い形の file が今回と同じ回なら、この形の名前に直す案も見せる
   - 迷ったら案件限定にする (持ち越しの事故の方が重い)。
2. 案を `資料メモ/.保存前/` に書き、`python3 scripts/check.py pii 資料メモ/.保存前 --allow 資料メモ/pii-allow.txt` を実行する (allow の file が無ければ `--allow` を付けない)。見つかった行は消すか一般化する (「山田さん (総務)」→「総務担当」)。通るまで見せない。
3. 本人に見せる。どの file に・何を足す/変える/消すかを、共通と案件限定に分けて短く並べる:

```
次回のために、次のことをメモに残してよいですか。

【事務所共通】(どの資料でも使います)
 1. 話し手の紹介: 「…」 (追加)
 2. 口調: 語尾は「です・ます」、事例は自分の経験から 1 つ (変更: 前回は「事例は 2 つ」)
【この顧問先のこの回だけ】(A 社 の「社会保険の説明」の続きの時だけ使います。file: 案件/2026-12_A社-社会保険の説明.md)
 3. 受け手: 社長と総務担当の 2 名、専門用語は少なめ
保存しないもの: 従業員の名前・連絡先・健康のことなど個人の情報

よければ「はい」、外したい番号があれば教えてください。
```

4. 了承された分だけ `.保存前/` から本来の場所に移し、`.保存前/` を消す。最後に `資料メモ/` 全体に同じ検査を実行して通ることを確かめる。話し手本人の氏名など本人が載せてよいと言った語は、本人の了承を得て `pii-allow.txt` に足す (顧問先側の個人の情報は足さない)。
5. 了承が無い・返事が無い時は保存しない。

保存しないもの: 顧問先の従業員や個人の氏名・連絡先・住所・生年月日・健康や障害の情報・マイナンバー・個人ごとの給与額・相談の中身そのもの。過去資料の本文の長い写し (口調の引用は短い言い回しだけ)。

## 訂正・削除・今回だけ

| 本人の言い方 | すること |
|---|---|
| 「それは違う、正しくは…」 | メモの値を直し、出典を「本人の訂正 <日付>」にする。`訂正ログ.md` に「<日付> 訂正: <項目名>」を足す |
| 「それは消して」「もう使わないで」 | 項目を消す。`訂正ログ.md` の「使わない」一覧に、中身を書かずに要点だけ足す (例「旧事務所名を使わない」「A 社の件を他で使わない」)。口調の抽出 (`voice.md`) でも同じ内容を拾い直さない |
| 「今回だけ…にして」 | メモは書き換えない。BRIEF の決定ログに種類「今回だけ」で書く。次回は元のメモの値を推奨答にする |
| 「この顧問先のメモを全部消して」 | 名前に `<呼び名>` を含む `案件/` の file を全部消す (`_<呼び名>-` の形も、回の入っていない古い形も。消す file 名を先に見せて確かめる)。訂正ログに「<呼び名> のメモを削除 <日付>」と書く |

訂正や削除の前後で、何が変わるかを 1 行で見せてから実行する。

## 一覧で見せること (R-11)

最後の報告に、次の 3 つを分けて書く:
- 読んだ物 (メモの file・過去資料・参考資料)
- 外に送った物 (検索した言葉・取得した URL)
- 保存した物 (メモのどの file に何を足したか)
