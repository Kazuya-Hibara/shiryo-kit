# memory.md — P0 と P8 のメモリー (一度聞いたことを次に活かす)

## 目的

2 回目以降、同じことを聞き直さない。前回の答えを推奨答として出し、変わった所だけ聞く。
ただし、別の顧問先・別の回の情報を持ち込まない。顧問先の個人情報は保存しない。保存も訂正も本人が決める。

## 置き場所

利用者が選んだ作業フォルダの中の `資料メモ/` (名前は仮。本人が別の名前・場所を選んだらそれに従い、BRIEF の環境欄に書く)。
skill フォルダの中には保存しない (更新で消える・書けないことがある)。各ツールの自動メモ機能にも頼らない (無効な環境がある)。正本はこのフォルダの file。

```
資料メモ/
  README.md            このフォルダの説明 (人が読んで分かる 10 行程度)
  事務所共通.md         どの案件でも使う: 話し手・事務所の紹介 (資料に載せてよい範囲) / 口調と構成の癖 (`voice.md` の形) /
                       型と見た目の好み / 本人の方針 (いつも入れる・言わないこと) / よく使う出典 (手がかり) / 何度も出てくる受け手
  案件/<呼び名>.md      その顧問先・その回だけ: 受け手 / 場面 / 言わないこと / 前に説明した話題 — 同じ相手の時だけ読む
  訂正ログ.md           訂正・削除の記録と「使わない」一覧
  pii-allow.txt        個人情報の検査で通してよい語 (本人が載せてよいと言った話し手の氏名・事務所名など)
```

- 呼び名は本人に決めてもらう (例「A 社」「商工会 本部 秋のセミナー」)。顧問先の正式名を保存するかは本人に聞き、望まない限り呼び名だけにする。
- 既に `資料メモ/` が別の形で置かれていても、事務所共通と案件限定の区別が読み取れればそのまま使う。保存の時に、この形に寄せる案を見せる。
- 各項目には、値・どこから来たか (どの案件で本人が言った / どの file から抜いた)・最後に確かめた日を書く。

```markdown
## 話し手の紹介
- 値: 社会保険労務士。中小企業の労務相談を中心に…
- 出典: 20261018-就業規則セミナー のヒアリング 1 回目、本人の言葉
- 確認日: 2026-10-18
```

## 読む時 (P0)

1. 作業フォルダとその親を見て `資料メモ/` を探す。見つかったら「メモが見つかりました: <path>」、無ければ「メモは見つかりませんでした。今回の内容は、最後に保存するか確認します」と言う。
2. `訂正ログ.md` を先に読み、「使わない」に当たる内容は以後使わない。
3. `事務所共通.md` を読む。
4. `案件/` は、今回の相手の呼び名の file だけを読む。相手が分からなければ、ヒアリングの最初の問いに「どの顧問先 (どの回) 向けですか」を入れ、答えが出てから読む。他の呼び名の file は開かない・中身を見せない。
5. 読んだ値は推奨答として使う。確定値としては扱わない (本人が「はい」と言って初めて今回の要件になる)。
6. `sources.md` の出典は、使う前に必ず取り直す (`evidence.md` §7)。

## 保存する時 (P8)

1. 案件の終わり (または本人が望んだ時) に、保存の案を作る。分け方:
   - 事務所共通: 話し手・事務所の紹介、口調、型の好み、よく使う出典、何度も出てくる受け手
   - 案件限定: その顧問先・その回の受け手と事情
   - 迷ったら案件限定にする (持ち越しの事故の方が重い)。
2. 案を `資料メモ/.保存前/` に書き、`python3 scripts/check.py pii 資料メモ/.保存前 --allow 資料メモ/pii-allow.txt` を実行する (allow の file が無ければ `--allow` を付けない)。見つかった行は消すか一般化する (「山田さん (総務)」→「総務担当」)。通るまで見せない。
3. 本人に見せる。どの file に・何を足す/変える/消すかを、共通と案件限定に分けて短く並べる:

```
次回のために、次のことをメモに残してよいですか。

【事務所共通】(どの資料でも使います)
 1. 話し手の紹介: 「…」 (追加)
 2. 口調: 語尾は「です・ます」、事例は自分の経験から 1 つ (変更: 前回は「事例は 2 つ」)
【この顧問先だけ】(A 社 向けの時だけ使います)
 3. 受け手: 社長と総務担当の 2 名、専門用語は少なめ
保存しないもの: 従業員の名前・連絡先・健康のことなど個人の情報

よければ「はい」、外したい番号があれば教えてください。
```

4. 了承された分だけ `.保存前/` から本来の場所に移し、`.保存前/` を消す。最後に `資料メモ/` 全体に同じ検査を実行して通ることを確かめる。話し手本人の氏名など本人が載せてよいと言った語は、本人の了承を得て `pii-allow.txt` に足す (顧問先側の個人の情報は足さない)。
5. 了承が無い・返事が無い時は保存しない。

保存しないもの: 顧問先の従業員や個人の氏名・連絡先・住所・生年月日・健康や障害の情報・マイナンバー・個人ごとの給与額・相談の中身そのもの。過去資料の本文の長い写し (口調の引用は短い言い回しだけ)。

## 訂正・削除・今回だけ

| 本人の言い方 | すること |
|---|---|
| 「それは違う、正しくは…」 | メモの値を直し、出典を「本人の訂正 <日付>」にする。`訂正ログ.md` に「<日付> 訂正: <項目名>」を足す |
| 「それは消して」「もう使わないで」 | 項目を消す。`訂正ログ.md` の「使わない」一覧に、中身を書かずに要点だけ足す (例「旧事務所名を使わない」「A 社の件を他で使わない」)。口調の抽出 (`voice.md`) でも同じ内容を拾い直さない |
| 「今回だけ…にして」 | メモは書き換えない。BRIEF の決定ログに種類「今回だけ」で書く。次回は元のメモの値を推奨答にする |
| 「この顧問先のメモを全部消して」 | `案件/<呼び名>.md` を消し、訂正ログに「<呼び名> のメモを削除 <日付>」と書く |

訂正や削除の前後で、何が変わるかを 1 行で見せてから実行する。

## 一覧で見せること (R-11)

最後の報告に、次の 3 つを分けて書く:
- 読んだ物 (メモの file・過去資料・参考資料)
- 外に送った物 (検索した言葉・取得した URL)
- 保存した物 (メモのどの file に何を足したか)
