# エージェント版の準備と使い方 (Claude Code・Codex をお使いの方向け)

このページは、**Claude Code か Codex を既に使っている方 (または入れてもよい方)** 向けです。
ターミナルや GitHub が初めての方は、このページは読まなくてかまいません。[チャット版](../chat/README.md) (ふだんの ChatGPT・Claude・Gemini に指示文を貼るだけ) から始めてください。

道具の全体の説明・見本・限界は [README](../README.md) にあります。

> **まだ「未検証」です。** 作った側の Mac で、架空のデータを使って確かめただけです。Windows 用の install.ps1 は一度も動かしていません。

## はじめての準備 (エージェント版)

### 0. 先に要るもの

- **Claude Code か Codex** (どちらか片方で動きます)。どちらも、**有料のプランに入っている** と考えてください。

  | 使う道具 | 要るプラン (2026-10-18 時点の公式の案内) |
  |---|---|
  | Claude Code | **Claude の有料プラン** (個人なら Pro か Max、会社なら Team か Enterprise)。**無料プランでは使えません。** 開発者向けの API の契約でも使えます (文字で操作する版だけ) |
  | Codex | **ChatGPT の有料プラン** (個人なら Plus か Pro、会社なら Business・Enterprise・Edu)。公式には無料・Go のプランにも含まれますが、使える範囲とモデルが限られ、おすすめのモデル (下の §3) が使えるかは確かめていません |

  - 金額は各社がよく変えるので、ここには書きません。申し込みは、Claude なら claude.ai、ChatGPT なら chatgpt.com にログインすると出る「アップグレード」(Upgrade) の案内からします。
  - 入れ方 (公式の案内):
    - Claude Code: **ターミナル (黒い画面) を使ったことがない方は、デスクトップアプリ** を入れてください。「デスクトップアプリを始める」https://code.claude.com/docs/ja/desktop-quickstart (日本語のページ。公式にも「ターミナルを使用せずに」使えると書いてあります)。文字で操作する版は「高度なセットアップ」https://code.claude.com/docs/ja/setup 。
    - Codex: いまは ChatGPT のデスクトップアプリの中で使います (アプリの中で ChatGPT か Codex を選びます)。入れ方は「ChatGPT desktop app」https://learn.chatgpt.com/docs/app (英語のページです。ブラウザの翻訳機能で日本語にして読めます)。文字で操作する版は「Codex CLI」https://learn.chatgpt.com/docs/codex/cli 。契約と使える範囲は https://learn.chatgpt.com/docs/pricing 。
- **この shiryo-kit のフォルダ。** GitHub の shiryo-kit の **いちばん上のページ** (このページを GitHub で見ているなら、ページの上の方にある「shiryo-kit」の文字を押すと戻れます) の、緑色の「Code」ボタン →「Download ZIP」で取り、ZIP を開いて (展開して) ください。展開すると、ふつうは `shiryo-kit-main` という名前のフォルダができます。

### 1. shiryo-kit を入れる

やり方は 2 つあります。どちらも、することは同じです。

**やり方 A — AI に頼む (おすすめ)**
Claude Code か Codex を、展開したフォルダ (`shiryo-kit-main` など) で開きます。Claude のデスクトップアプリなら、上の「Code」タブで「Select folder」を押して、このフォルダを選びます。ChatGPT のデスクトップアプリ (Codex) なら、Codex を選んでフォルダを開きます。開いたら、次のように頼みます。

- Claude Code なら「このフォルダの install.sh を --claude を付けて実行して」(Windows は「install.ps1 を -Claude を付けて実行して」)
- Codex なら「このフォルダの install.sh を --codex を付けて実行して」(Windows は「install.ps1 を -Codex を付けて実行して」)

AI がコマンドを実行してよいかを確かめてきたら、許可してください (Codex は、作業中のフォルダの外 (スキルの置き場所) に書き込むので、たいてい確かめてきます)。
うまくいくと、AI の返事か画面に「[Claude Code] コピーしました: …」(または「[Codex] コピーしました: …」、2 回目以降は「新しい版に入れ替えました」) と「終わりました。」が出ます。「止めました」と出た時は、下の「うまくいかない時」をご覧ください。

**やり方 B — 自分でコマンドを打つ**

1. コマンドを打つ画面を、展開したフォルダで開きます。
   - Mac: 「アプリケーション」→「ユーティリティ」→「ターミナル」を開き、`cd ` (cd と半角の空白) と打ってから、展開したフォルダをターミナルの画面にドラッグして、Enter を押します。
   - Windows: エクスプローラーで展開したフォルダを開き、上のアドレス欄 (フォルダの場所が書いてある所) をクリックして `powershell` と打ち、Enter を押します。
2. 次のどれか 1 つを打って Enter を押します。

| 入れる先 | Mac・Linux | Windows |
|---|---|---|
| Claude Code | `./install.sh --claude` | `powershell -ExecutionPolicy Bypass -File .\install.ps1 -Claude` |
| Codex | `./install.sh --codex` | `powershell -ExecutionPolicy Bypass -File .\install.ps1 -Codex` |
| 両方 | `./install.sh` | `powershell -ExecutionPolicy Bypass -File .\install.ps1` |

Windows の `-ExecutionPolicy Bypass` は、「ダウンロードしたスクリプトは実行しない」という Windows の既定の止めを、**この 1 回の実行だけ** 外す指定です。Windows の設定そのものは変えません。
**Windows 用の install.ps1 は、まだ一度も実際に動かしていません。** うまくいかない時は、下の「うまくいかない時」をご覧ください。

このコマンドがすることは、`skill/shiryo-kit` フォルダを、AI がスキル (追加の手順書) を読みに行く場所にコピーすることだけです。

- Claude Code: `~/.claude/skills/shiryo-kit` (Windows では `C:\Users\<あなたの名前>\.claude\skills\shiryo-kit`)
- Codex: `~/.agents/skills/shiryo-kit` (Windows では `C:\Users\<あなたの名前>\.agents\skills\shiryo-kit`)

`~` は、あなたのユーザーのフォルダ (Mac なら Finder の「ホーム」、家の形のアイコンのフォルダ) のことです。名前が `.` で始まるフォルダは、ふだんは隠れていて見えません。
他のスキルや設定には触りません。同じ名前で中身が shiryo-kit でないフォルダが既にあれば、上書きせずに止まります。何度実行しても同じ結果になります。新しい版が出たら、新しいフォルダで同じことをすれば入れ替わります。
(直す人向け: `--link`、Windows は `-Link` を付けると、コピーの代わりにこのフォルダへのリンクを張ります。)

入れたら、Claude Code・Codex を一度閉じて開き直してください。

### 2. 初めて使う時に、AI が準備するもの

PowerPoint と PDF を書き出すために、次のものが要ります。足りない物があると、AI が「何を・なぜ入れるか」を説明して、**あなたの了承を得てから** 入れます。どれも、プログラムを動かすための土台の部品で、無料です。断った場合は、作った資料をブラウザで見るページ (HTML) のまま渡し、PDF にする手順を案内します。

| 要るもの | 何に使うか | 入れ方の例 (AI が実行します) |
|---|---|---|
| Node.js 22 以上 | スライドを描いて、PowerPoint・PDF にする | Mac: `brew install node` (brew は Mac にソフトを入れる道具。無ければ公式サイト https://nodejs.org/ から入れます) / Windows: `winget install OpenJS.NodeJS.LTS` |
| Google Chrome か Microsoft Edge | スライドを一度画面に描いて、文字の位置と大きさを測る | ふつうは既に入っています。Windows には Edge が最初から入っています |
| Python 3.10 以上と、部品 python-pptx・lxml | PowerPoint のファイルを組み立てる・確かめる | Mac・Linux: shiryo-kit 専用の場所 (`~/.shiryo-kit-venv`) に入れます / Windows: `py -m pip install python-pptx lxml` |

### 3. おすすめのモデル (AI の種類と、考える深さ)

AI には種類 (モデル) と、どれだけ考えてから答えるか (effort) の設定があります。shiryo-kit は「間違えないこと」を優先するので、**いちばん賢い種類を、よく考える設定** で使うのがおすすめです。
画面で選ぶ時は、Claude Code なら名前に **「Opus」** と付くもの、Codex なら **「gpt-6-astra」** を選び、考える深さは **「high」(高)** にします。速さは落ちますが、資料の間違いが減ります。

| 使う AI | おすすめ | 設定の仕方 |
|---|---|---|
| Claude Code | **Opus 5.5、effort (考える深さ) は high** | デスクトップアプリでは画面のモデル選択で Opus 5.5 を選ぶ。文字で操作する版では、起動の時に `claude --model opus --effort high` |
| Codex | **gpt-6-astra、reasoning effort (考える深さ) は high** | デスクトップアプリでは画面のモデル選択で選ぶ。文字で操作する版では、起動の時に `codex -m gpt-6-astra -c model_reasoning_effort="high"` |

分からない時は、AI に「モデルを Opus 5.5 の high にする方法を教えて」と聞いてもかまいません。
正直に書くと、**Codex (gpt-6-astra) は Claude Code (Opus 5.5) より品質が少し落ちます** (作った側の評価です。どこにどれだけ差が出るかは、試験で記録して更新します)。全部の工程は Codex でも動くように作ってあります。

## 使い方

### はじめて

1. 資料を置くためのフォルダを、shiryo-kit のフォルダとは別に新しく作ります (例:「書類」の中に「資料づくり」)。展開した shiryo-kit のフォルダの中では作業しません。そのフォルダで Claude Code か Codex を開きます。過去の資料 (pptx・pdf・Word) があれば、このフォルダに入れておくか、場所を伝えてください。
2. ふつうの言葉で頼みます。
   - 「セミナー資料を作りたい」
   - 「顧問先に、来年の制度の変更を説明する資料がほしい」
   - 「この前のセミナー資料をもとに、読み原稿も付けて作り直して」

   名前で呼ぶこともできます (Claude Code は `/shiryo-kit`、Codex は `$shiryo-kit`)。

### 聴き取りはこんな感じです

最初に、AI が読んだ物 (メモ・過去資料) と読めなかった物を一覧で見せます。そのうえで、まとめて質問が来ます。

```
資料づくりの前に、まとめて確認させてください。おすすめの答えを書いてあります。
このままでよければ「はい」、変えたい所だけ番号で教えてください (例: 「3: 40分」)。

1. 目的 — おすすめ: 「就業規則の見直しが必要な会社に、相談に来てもらう」
   (目的で最後のまとめ方が変わります)
2. 聞く人 — おすすめ: 従業員 10〜30 人の会社の社長・総務担当
   A. このまま  B. 人事の専門担当が多い  C. その他 (書いてください)
3. 時間と形 — おすすめ: 60 分、会場で投影して話す + 同じ内容を PDF で配る
...
```

- 答えによって、もう 1〜2 回まとめて聞くことがあります。何往復するかは AI が内容を見て決めます。
- 見た目の「型」(セミナー・顧問先説明・提案・報告の 4 種) は、[README の見本](../README.md#出来上がりの見本) のような画像を見て選べます。型に無い資料 (社内研修の配布資料など) も、近い型を組み替えて作れます。配色は 3 種類 (あたたかい茶・落ち着いた紺・墨色) から選べます。事務所の PowerPoint のひな形をそのまま使う機能はありません。
- 最後に要約が出ます。あなたの言葉と、AI の推測 (「(推測)」と付きます) を分けて書きます。おすすめの答えに「はい」と言ったところも、ここでもう一度見直せます。「この内容で」と答えると作り始めます。
- 作っている途中で新しい質問はしません。例外は、原典を読んで「前提が変わる」と分かった時だけで、その時は理由を見せて 1 回でまとめて聞きます。

急いでいる時は「質問はいいから作って」と言えば、全部の項目をおすすめの答えで埋めて 1 回で見せ、「この前提で作ってよいですか」と聞きます。この「はい」だけは省きません。

### 受け取るもの

作業フォルダの中に、資料ごとのフォルダ (例: `資料/20261018-就業規則セミナー/`) ができます。

| もの | ファイル | 中身 |
|---|---|---|
| スライド (PowerPoint) | `out/<資料名>.pptx` | 文字は PowerPoint の文字、表は PowerPoint の表なので、そのまま直せます。読み原稿は「ノート」に入っています |
| PDF | `out/<資料名>.pdf` | 配る・送る用 |
| 読み原稿 | `out/<資料名>_読み原稿.md` | スライドごとに、声に出して話す言葉。字数と時間の目安つき |
| 出典の一覧 (出典台帳) | `ledger.md` | [README の見本](../README.md#出来上がりの見本) の形。主張ごとの区分・URL・引用・確かめた日・いつから有効か |
| 点検の結果 | `review/` | 別の AI の点検結果と、別の AI が本当に点検したことの記録 |
| 資料の要件 | `BRIEF.md` | 聴き取りで決めたこと。あなたの承認の記録つき |

`.md` のファイルはふつうの文字のファイルです。メモ帳 (Windows) やテキストエディット (Mac) で開けます。

最後に AI が、次のことを必ず報告します。

- ファイルの場所
- 点検の状態 (「検品済み」「検品済み・指摘が残っています」「未検品」のどれか) と、その理由
- [要確認] の件数と一覧 (何を・どこで確かめればよいか)
- あなたが言ったことで、原典で照らしていないもの
- 読んだ物・外に送った物・保存した物の一覧

### 直したい時

ふつうの言葉で伝えてください。「3 枚目の 2 行目を『〜』に変えて」「全体をもう少しやわらかい言い方に」「5 枚目と 6 枚目を入れ替えて」。
数字や制度の説明を直した時は、AI が出典の確認と点検をやり直してから渡します (直した版をそのまま点検済みとは言いません)。

**PowerPoint を手で直すのは、最後にしてください。** AI に直しを頼むと、AI は元の資料から PowerPoint を作り直すので、手で直した所は消えます。また、手で直したファイルは、点検した版とは別のものとして扱います。

画面で直接指して直す方法 (ChatGPT のデスクトップアプリの「Annotate」、Claude のデスクトップアプリの「要素の選択」) にも対応するつもりですが、**まだ実際に試していません (未検証)。** 今は言葉で伝えてください。試してみたい方向けの手順は [compat.md](compat.md) の §4 にあります。

### 2 回目から

前回のメモがあれば、AI が最初に「メモが見つかりました」と言い、前回の答えをおすすめの答えとして出します。同じことを一から聞き直しません。変わった所だけ答えてください。
別の顧問先・別の回の資料を作る時は、前の顧問先だけのメモは読みません。

### うまくいかない時

| こんな時 | すること |
|---|---|
| 入れる時に「止めました」と出た | 同じ名前で中身の違うフォルダが既にあります。表示された場所のフォルダを確かめ、要らなければ名前を変えてから、もう一度実行してください |
| Windows で install.ps1 がうまく動かない | Claude Code か Codex に「install.ps1 がこう表示された。原因を調べて」とそのまま貼って頼んでください。手で入れる場合は、`skill` フォルダの中の `shiryo-kit` フォルダを、上の「入れる先」の場所にコピーするだけです |
| 「/shiryo-kit」「$shiryo-kit」が見つからない | Claude Code・Codex を閉じて開き直してください。それでも出なければ、入れる先の場所に `shiryo-kit` フォルダがあるか確かめてください |
| 途中で止まった・会話を閉じてしまった | 同じフォルダで開き直し、「この資料の続きをやって」と頼んでください。資料ごとのフォルダに、決めたこと (BRIEF.md) と途中の物が残っています |
| 出典が全部 [要確認] になる | AI がインターネットに出られていません。Codex では、ネットへの接続の許可を求められたら許可してください。公的なページの本文を自分でコピーして渡せば、それを原典として使います |
| 「PowerPoint はまだ作れていません」と言われた | 上の「AI が準備するもの」が揃っていません。AI の説明に沿って入れるか、HTML のまま受け取ってください |

不具合や分からない所は、[README の「お問い合わせ」](../README.md#お問い合わせ) の方法でお知らせください。

## メモの保存場所と、直し方・消し方

- **保存場所**: 資料を作っている作業フォルダの中の `資料メモ/` フォルダです。あなたのパソコンの中にあり、ふつうの文字のファイルなので、メモ帳などで開いて読めます。
  - `資料メモ/事務所共通.md` — どの資料でも使うこと (話し手・事務所の紹介、口調、型の好み、よく使う出典)
  - `資料メモ/案件/<呼び名>.md` — その顧問先・その回だけのこと。同じ相手の資料の時だけ読みます
  - `資料メモ/訂正ログ.md` — 直した・消した記録と、「もう使わない」一覧
- **保存する前に必ず見せます。** 「次回のために、次のことをメモに残してよいですか」と一覧が出るので、外したい番号を言うか「はい」と答えてください。返事が無ければ保存しません。
- **顧問先の個人の情報 (従業員の名前・連絡先・健康のこと・給与など) は保存しません。** 保存の前に、プログラムで個人情報らしいものが残っていないかを調べます。顧問先の名前も、あなたが望まない限り「A 社」のような呼び名で残します。
- **直す・消す**: AI にそのまま言ってください。
  - 「事務所の紹介はそれじゃない。正しくは〜」→ メモを直します
  - 「それは消して」「もう使わないで」→ 消して、「使わない」一覧に入れます (同じことを拾い直しません)
  - 「今回だけ〜にして」→ メモは変えず、今回の資料だけ変えます
  - 「A 社のメモを全部消して」→ その顧問先のメモを消します
- 全部消したい時は、`資料メモ/` フォルダをご自分で削除してもかまいません。

Claude Code や Codex が持っている「自動で覚える機能」には頼っていません。メモの正本はこのフォルダのファイルです。

## 何を読み、何を外に送り、何を保存するか

| | 中身 |
|---|---|
| **読む物** | 作業フォルダの `資料メモ/`、あなたが渡した・置いた過去資料と参考資料。読んだ物と読めなかった物は、最初に一覧で見せます。読む途中で見えた顧問先の個人の情報は、メモにも資料にも写しません |
| **外に送る物 (AI の会社へ)** | Claude Code・Codex は、会話と AI が読んだファイルの中身を、それぞれの会社 (Claude Code は Anthropic、Codex は OpenAI) のサーバーに送って処理します。これは shiryo-kit に限らず、この 2 つの道具の仕組みです。送った内容がどう扱われるか (学習に使われるかなど) は、契約と設定で違います |
| **外に送る物 (原典の確認)** | 原典を探すための検索の言葉と、取得するページの URL がインターネットに出ます。検索の言葉には、顧問先の名前や個人の情報を入れない決まりにしています。送った検索の言葉と URL は、最後に一覧で見せます |
| **保存する物** | あなたのパソコンの作業フォルダの中だけです: 資料ごとのフォルダ (要件・出典・取得した原典の写し・スライド・点検の記録) と、了承をもらった分の `資料メモ/`。shiryo-kit のフォルダ自体には何も保存しません |

顧問先の情報について、使う前にしていただきたいこと:

- **過去資料を作業フォルダに入れる前に、従業員の名前・連絡先・健康のことなど、顧問先の個人の情報が入っていないかを見て、入っていれば消すか伏せてください。** AI は写さない決まりですが、読んだ時点で AI の会社には送られます。入れないのがいちばん確かです。
- お使いの契約で、会話の内容が AI の学習に使われる設定になっていないかを、各社の設定画面 (「プライバシー」や「データ」の項目) で確かめてください。守秘義務との関係は、ご自身の判断になります。

### Claude Slides を使う時だけ、保存先が変わります

Claude Code では、仕上げを「Claude Slides」(claude.ai のスライド編集の画面) に任せることもできます。「Claude Slides で仕上げて」と頼んだ時だけ使います。

- **スライドの内容が claude.ai (Anthropic のサーバー) に保存されます。** 最初は作った本人だけが見られる設定ですが、あなたのパソコンの外に残ります。顧問先の情報を入れてよいかは、ご自身で判断してください。使う前に AI が必ずこのことを伝えて確かめます。
- claude.ai にログインした Claude Code が要ります (API の契約での接続や、一部の会社の管理設定では使えません)。
- そこから PowerPoint に書き出した時に、文字が直せる形になっているか・日本語の書体が保たれるかは、**まだ確かめていません (未検証)。** 書き出したファイルは AI がプログラムで確かめ、確かめられなければ「未検品」として渡します。
- 点検は、Claude Slides に渡す前の資料で済ませておきます。

OpenAI の同じような機能 (Codex の Presentations) は、この道具では案内しません。中で使われている部品の利用条件が「内部の評価・試験目的のみ、商用不可」となっているためです。
